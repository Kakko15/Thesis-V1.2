# Audit evidence, 2026-09-05

Source revision: `1426252313b11b6015520cef7d74cba696ab28f6`.

These files support the [audit report](../../../CODEBASE_SECURITY_AUDIT_2026-09-05.md). They contain synthetic examples. Passing reproduction probes mean the reported behavior occurred; they do not mean the defects are fixed.

## Provenance and limits

- `test_audit_reproductions.py`: 14 offline cases covering F02-F12. Three cases exercise multipart parsing on separate routes; two exercise guest budget accounting. F04 also relies on the frontend source review. HTTP probes use FastAPI's local TestClient. Supabase identity/database and model behavior are mocked where required, and unexpected HTTP transport calls are blocked. The database-failure probes model the relevant commit/delete outcomes; they do not exercise a live Postgres transaction.
- `reproductions.xml`: pytest-generated result for those 14 cases.
- `audit_browser.mjs`: F01 reproduction using the real E2E bundle's pages and query cache, synthetic Alice/Bob auth fixtures and intercepted API responses. It switches accounts within the SPA. Production Supabase sign-in/verification is not exercised. External browser requests are blocked.
- `browser-reproduction.json` and `cross-account-cache.png`: generated by that browser harness. The screenshot shows only synthetic account/report data.
- `pip-audit.json`: direct pip-audit 2.10.1 JSON output for the backend requirements lock, with 98 dependencies and no reported vulnerabilities or skipped packages.
- `npm-audit.json`: a manually saved transcription of the production npm advisory result, preserving the reported vulnerability and metadata fields. It is not a byte-for-byte capture of the command's stdout. Advisory results are time dependent.

## Reproduce the Python observations

Use the installed backend development/test dependencies. From `rag-thesis-backend` in PowerShell:

```powershell
.\.venv\Scripts\python.exe -B -m pytest -c pytest.ini ..\docs\evidence\security\audit-2026-09-05\test_audit_reproductions.py -q --junitxml=..\docs\evidence\security\audit-2026-09-05\reproductions.xml
```

The probes import the project's fake test configuration before importing the application. They must remain separate from normal regression tests until their expectations are changed to assert corrected behavior.

## Reproduce the browser observation

With frontend dependencies and the project's Playwright Chromium already installed, run `npm.cmd run test:e2e` from `rag-thesis-frontend` to produce the existing `dist-e2e` bundle. Then, from the repository root:

```powershell
node docs/evidence/security/audit-2026-09-05/audit_browser.mjs
```

The harness serves the bundle on `127.0.0.1:4174`, closes its browser/server when finished and overwrites its JSON/screenshot evidence. The existing E2E suite uses port 4173. No live backend is required.

## Refresh dependency advisories

From `rag-thesis-backend`, the original Python lock audit command was:

```powershell
.\.venv\Scripts\python.exe -m pip_audit --no-deps --disable-pip -r requirements.lock --format=json --output=../docs/evidence/security/audit-2026-09-05/pip-audit.json
```

From `rag-thesis-frontend`, use `npm.cmd audit --omit=dev --json` to query the current production advisory result. These commands contact advisory/package services. They do not test exploit reachability or update application dependencies.
